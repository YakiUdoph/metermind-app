==================================================

1. WHAT METERMIND IS

==================================================




MeterMind is an AI-powered autonomous payment and spending intelligence agent.




Businesses give MeterMind a budget and rules.




MeterMind can then:




• understand spending requests

• decide whether a payment should be approved

• enforce budgets and spending rules

• choose appropriate payment routes

• execute permitted machine-to-machine payments

• track what was spent

• detect unnecessary or abnormal spending

• show how much money it helped save

• explain why it made each decision




Simple example:




A company tells MeterMind:




“Give my AI research agents a $1,000 monthly budget.

Never spend more than $50 on one API call.

Prefer cheaper providers when quality is similar.”




MeterMind becomes the intelligent financial control layer between the AI agents and the services they pay for.




The product should visually communicate:




CONTROL

INTELLIGENCE

MONEY

AUTONOMY

TRUST

REAL-TIME DECISION MAKING




This should feel like financial infrastructure for the agent economy.

==================================================

• compact interface

Use a dark surface hierarchy inspired by the attached Linear DESIGN.md:

6. CURSOR ↔ ORB INTERACTION

==================================================




On desktop, the orb should subtly react to the mouse.




When the cursor moves:




• orb rotates slightly toward cursor

• internal particles shift

• nearby light subtly responds

• surrounding data points have slight parallax

• movement should be smooth and premium




DO NOT make the orb chase the cursor.




The user should feel that MeterMind is AWARE of them.




Think:




cursor moves →

financial intelligence notices →

system subtly responds.




Add an extremely restrained cursor trail inspired by the MotionSites mouse-trail reference.




The trail should fade quickly.




No rainbow trail.

No giant particles.

No childish effects.




Prefer tiny lime/white computational particles or faint data traces.




On mobile:

disable cursor-specific effects and use subtle autonomous orb movement instead.

24. MOTION SYSTEM

==================================================




Motion must feel intentional.




Use approximately 200–400ms transitions for normal UI.




Use:




ease-out

subtle opacity

border transitions

small translations

controlled blur

small parallax




Orb movement can be slower and more atmospheric.




Cards may shift 2–4px on hover where appropriate.




Buttons should have tactile hover/press states.




Charts may animate into view.




Numbers may count upward once.




Live activity may gently update.




Natural-language rules should animate into structured controls.




DO NOT:




• animate everything

• make cards constantly float

• use excessive glowing

• use bouncing animations

• use huge scroll effects

• create distracting background particles everywhere
